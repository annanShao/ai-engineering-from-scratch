Ruler 01 · L01–L11 主线

内化 vs 外部

规划/自我批评/反思可以内化进 prompt;但 ground truth 验证、持久记忆、真实执行、时间感、副作用记账,必须外部 —— 再大的模型也修不了。

问:它把 ground truth 锁哪了?记忆怎么过夜?副作用怎么记账?三个答不上,基本是 demo。

Ruler 02 · L12 分水岭

谁拥有控制流图

下一步走哪,工程师写死的是 workflow,模型现场决定的是 agent。光谱:chaining → routing → parallel → orchestrator → eval-opt → agent。

问:看到"每条边都 conditional",立刻知道这是"以为在用 workflow,其实是 full agent 套壳"。

Ruler 03 · L14 换尺子

谁拥有 state

集中 owned(LangGraph:一份共享 state,整图崩)vs 分布 owned(actor:各自私有,单点崩别人继续)。前者是流程可靠性,后者是组织弹性。

问:state 是一份共享的、framework 拥有的,还是 N 份 actor 私有、只靠消息流动的?

Ruler 04 · L15 决胜问

笼子里装什么

那个"创造力孤岛"里,是一个 LLM 用 tools,还是一群 LLM 用人格 riff?一个 → LangGraph node 够;一群 → 才掏 CrewAI Crew。

问:你这问题真需要多个 LLM,还是 1 个 LLM + 多 tools 就够?80% 是后者。

Ruler 05 · L13–L18 光谱

SDK 收什么进黑盒

LangGraph=state-first / CrewAI=role-first / OpenAI=handoff-first / Claude=harness-first / actor=正交。第一方=零配置换锁定;开源第三方=要配置换自由。

问:它把 graph/state/handoff/observation/security 五件事各放在哪一端?

Ruler 06 · L18 价值分层

该爬到栈的哪一层

裸 REST → Client SDK → 轻量 runtime → Agent SDK → 重型框架 → workflow engine。唯一无条件该升的是 0→1;其余每跳都要先掏出痛点。

问:我撞到了什么痛点,所以需要这一层?说不出痛点的升级就是交复杂度智商税。

Ruler 07 · L22 新约束

延迟即正确性

前 21 节可以"慢点没关系,对就行";语音 agent 迟 500ms 用户就重复/挂断 —— 慢本身就是一种错。任何实时 agent 都活在延迟预算里。

问:这条链每个组件加 50–200ms,上线前把整条链加起来了吗?

L01

The Agent Loop · ReAct

Yao et al. 2022 — ReAct: Reasoning + Acting

ReAct 真正的瓶颈不是模型,是 observation formatter —— 你把世界翻译成什么样的文字给模型看,决定了它能不能想清楚。

L02

ReWOO / Plan-and-Execute

Xu et al. 2023

ReWOO 冻结计划,Plan-and-Execute 计划可重写 —— 差别就一个 replan(question, plan, evidence) 节点。

L03

Reflexion · Verbal RL

Shinn et al. 2023

把"失败"变成下一轮 prompt 的一段 verbal memory —— 不改权重,改上下文。

L04

Tree of Thoughts / LATS

Yao 2023 · Zhou 2023 · MCTS/UCT

UCT 的 c 是好奇心调节器:调大更 exploration。Q 值是过去,√(ln N / n) 是未来。

L05

Self-Refine and CRITIC

Madaan 2023 · Gou 2023

Self-Refine 是闭环自评;CRITIC 把评分员换成外部工具 —— 幻觉天花板从"模型自身能力"变成"外部 ground truth 精度"。独立性阶梯:外部工具 > 异模型 > 异 prompt > 自评。

L06

Tool Use & Function Calling

Toolformer, Schick 2023 · BFCL

tool 出错不该 raise,该把错误塞回 observation 让模型自己看见再改 —— 错误也是一种感知。

L07

MemGPT / Virtual Context

Packer et al. 2023

大 context 修不了 dilution,因为 dilution 是注意力行为问题不是容量问题 —— 把 OS 虚拟内存搬来,让模型自己决定哪段 page in。

L08

Generative Agents · Memory Blocks

Park et al. 2023 (Smallville) · Letta

记忆三维:Recency / Importance / Relevance,少一维就塌一边。每天 reflect 一次,把流水账压成判断。

L09

Hybrid Memory · Mem0

Mem0 · fusion scoring

fusion 用加权和不用分层,因为分层假设维度有绝对优先级 —— 真实场景要"relevance 弱但 recency+importance 高"能被补偿出来。

L10

Skill Libraries · Voyager

Wang et al. 2023 (TMLR'24) · ZPD Vygotsky 1978

飞轮 = 刚高于当前能力的任务(最近发展区)+ 可执行 JS 函数库。前者保证有挑战不挫败,后者保证学过的不会忘。

L11

Planning: HTN & Evolutionary

ChatHTN Gopalakrishnan 2025 · AlphaEvolve Novikov/DeepMind 2025 · MAP-Elites Mouret&Clune 2015

AlphaEvolve 发现新算法时权重一次没动 —— 权重是基因,archive 是文化;它没改基因,改的是文化的传承机制。MAP-Elites 用行为多样性对抗种群塌缩。

L12–L18

框架篇 · taste 与五家光谱

从"会用零件"到"看穿框架"
L12

Anthropic Workflow Patterns

Schluntz & Zhang, Anthropic Dec 2024

Agent 不是更高级的 workflow,它是"把控制流所有权交给模型"的那个选择 —— 这个选择有代价,所以默认从 workflow 开始,让 agent 去挣它的复杂度。

L13

LangGraph · Stateful Graphs

durable execution · cf. Temporal 2019

卖点是"state 是一等公民,checkpoint 是默认行为"。checkpoint 太小 → 副作用 exactly-once 靠你自己幂等:LangGraph + 幂等 tool = 穷人版 Temporal。

L14

AutoGen · Actor Model

AutoGen v0.4 · actor model, Erlang 1986

Actor 用一条戒律(不许共享内存)同时换来三个工程奢侈品:无锁并发 / 容错隔离 / 透明分布。DLQ = 出错消息不丢不重试不阻塞,挪到角落让人看。

L15

CrewAI · Role-based Crews

CrewAI · Crew vs Flow

没发明新机制:把 graph + 多 agent 用"role/goal/backstory"重新打包。Flow 是脊柱(确定),需要创造力那一步嵌 Crew.kickoff()。Hierarchical = 最贵版 supervisor。

L16

OpenAI Agents SDK

handoff / guardrail / tracing

handoff = tool:白嫖 LLM 已有的 tool-selection 当 router,不需要专职 supervisor。Output guardrail 能挡愚蠢的攻击,挡不住耐心的攻击。

L17

Claude Agent SDK

harness-first · subagent / hooks

拿一个已在生产跑两年的 agent(Claude Code)拆开给你。8 个 hook 点位 > OpenAI 3 个 guardrail,因为它暴露的是实际生产用过的点位,不是设计出来的。

L18

Agno & Mastra · 轻量 Runtime

Agno (Python) · Mastra (TS)

= L01 ReAct loop + tool registry,写成高性能库,memory 和编排都甩给你。性能崇拜是选型第一大坑:2μs 只对"多短命 agent 高并发"值钱。

L19–L30

运营篇 · 从"造"到"审"

评测 / 感知 / 观测 / 失败 / 编排 / 方法论
L19

Benchmarks: SWE-bench, GAIA

Jimenez ICLR'24 · Mialon 2023 · Goodhart's Law

SWE-bench 可信因为 evaluator 是确定性测试套件不是 LLM 自评。报 benchmark 不提污染(SWE-bench+ 32.67% 泄漏)= 撒谎。看分布不看均值。

L20

Benchmarks: WebArena, OSWorld

Zhou ICLR'24 · Xie NeurIPS'24

GUI grounding 把失败拆成"知道做什么" vs "能不能在屏幕上指对地方"。轨迹效率:顶级 agent 用 1.4–2.7× 人类步数 —— 笨拙藏在步数里不藏在成功率里。

L21

Computer Use Agents

Claude Oct'24 · OpenAI CUA Jan'25 · Gemini Oct'25

untrusted input 铁律:屏幕上的字不是命令,只有用户直接指令是。Computer use 把 prompt injection 从信息安全升级成行动安全 —— 被劫持会替你按下不可撤销的按钮。

L22

Voice Agents · Pipecat, LiveKit

~600ms 延迟预算

不是文本 loop 接 TTS:它重构了 loop 的时序 —— 流式音频、turn detection 是个模型、barge-in 是反向通道。Multimodal vs Pipeline = 延迟换控制。

L23

OTel GenAI Conventions

OpenTelemetry GenAI SIG

span 树 = per-step trace + metrics + 轨迹的统一结构。默认不捕获 prose(privacy-by-default),外存+引用。绑标准别绑 vendor 私有命名。

L24

Observability Platforms

Langfuse / Phoenix / Opik / LangSmith

trace 是 substrate,eval 是长在上面的一层。只 tracing 不 evaluation = 昂贵的日志。LangSmith = LangChain 第一方闭源版。

L25

Multi-Agent Debate

Society of Minds, Du et al. ICML 2024

没有外部 ground truth 时,用多样性人造独立性。全部价值押在"这 N 个视角真独立吗" —— 同 prompt 同模型开 5 个 = 假独立,花 5 倍钱买 0 收益。

L26

Failure Modes (Agentic)

MASFT, Berkeley 2025

失败是设计缺陷不是模型局限。Cascading 最阴险:agent 不是崩溃,是自信地假装成功(400 当成功)。解药:成功由外部状态验证,不由 agent 宣布。

L27

Prompt Injection Defense · PVE

Greshake et al. AISec 2023 · indirect injection

处理检索来的 prompt = 让攻击者在你 agent 的 tool 面上执行任意代码。防御全在外部:PVE = Prompt-Validator-Executor,锚点是"动作符合用户原意吗"不是"内容可信吗"。

L28

Orchestration Patterns

supervisor / swarm / hierarchical

升级阶梯:单 agent → supervisor → swarm → hierarchical → debate,每档要具体可证伪的痛点。handoff drift 用 hop counter(= IP 包 TTL 的 agent 版)。

L29

Production Runtimes

request/stream/durable/queue/event/cron

运行时的形状决定哪些失败能活下来。按"时间 × 恢复成本"选。>30s 且不能重启必须上 durable。Observability 是承重墙,不是可选项。

L30

Eval-Driven Development

Anthropic Hybrid Norm · 拱顶石

把评测从最后一步提到第一步(agent 版 TDD),eval 分数当合并门禁。每道 guardrail 对应一个 eval case,否则是没测过的死代码。judge 要接 ground truth。

L31

Why Capable Models Still Fail

workbench manifesto

模型没搞错 Python,它搞错了"工作"。大多数 agent 失败故事,是穿着 prompt-engineering 外衣的 workbench 失败。Vercel 删 80% tool → 成功率 80%→100%。

L32

Minimal Workbench · 三文件

AGENTS.md + state + board

Long manuals get ignored, short routers get followed。最好的 AGENTS.md ≈ 把模型从 Haiku 升到 Opus,最差的比没有还糟。loop 闭合在 state 文件上,不是 chat 上。

L33

Instructions as Executable Constraints

rules → checks

agent-rules.md 是策略声明(软),write-tool authz + verification gate 是强制(硬)。check 读 git 真相不读 agent 自述。

L34

Repo Memory and State

schema + atomic write

坏的写入 = 被拒绝的写入。半写的 state 比没有 state 更糟 —— 没有 → fail loud;半写 → agent 信一份撒谎的 state。原子 rename 保证读者永远没有撕裂态。

L35

Initialization Scripts

startup probe · Trigger 原语

Fail loud, fail fast, fail in one place —— 工作台坏了就拒绝启动,不是让 agent 带残缺工作台硬跑。幂等 + 热路径无网络无 LLM。

L36

Scope Contracts

authorization policy

negative space(forbidden_files)是契约的一半。预防层(改文件前拒)+ 检测层(事后对 git 抓 creep)。scope creep 从"真诚的一步步"变成"改文件前就被拒"。

L37

Runtime Feedback Loops

feedback runner · Queue 原语

No exit, no progress:succeeded() 只认 exit 0。agent 再也没法自称成功,exit code 是唯一裁判。写盘前 redact,确定性截断(错误在 tail)。

L38

Verification Gates

deterministic gate · fails closed

一道 agent 贿赂不了的门:读 git 真相 + 重跑验收,不读自述。gate 侧无 LLM judge(judge 归 reviewer)。block 只有人能 override,签名记录。

L39

Reviewer Agent

separate role · Worker 原语

acceptance 必要不充分。gate 查"跑了吗",reviewer 查"对吗" —— 抓 gate 抓不到的"right tests, wrong problem"。独立 role(对 diff 只读)= 姿态变信号变。

L40

Multi-session Handoff

generated packet · Trigger

生成的不是手写的(手写忙时会跳过)。next_action 是承重字段。cleanup 是独立 check phase —— 脏树上的 handoff 不是 handoff,是转发的烂摊子。

L41

Workbench for Real Repos

before / after 实证

同模型同任务,差别不是智能是 surface。五指标:tests_run / acceptance / scope / handoff / reviewer。Harness, not model.

The security model · 皇冠上的一块

Prompt Injection 完整模型

三句话总纲,可以自己推。核心洞察是自己撞出来的:结构硬 / 模型软。

结构能保证边界不被伪造(content block + 特殊 token,tokenizer 层不可伪造),但不能保证模型尊重边界 —— 前者是密码学级的硬,后者是统计级的软。只要最终是把所有输入揉进注意力的文本模型,"把 untrusted 内容当命令"就永远是非零概率事件。

三句话总纲

① 内容全 untrusted —— 标记会漏、模型会上当,别赌。
② 安全必须外部 —— 不靠训模型"别上当",靠外部架构兜。
③ 锚点是动作-意图一致性 —— 不问"内容可信吗",问"这动作符合用户原意吗",在决定和执行之间用独立 validator 卡住。

workflow 和 agent 的本质区别?
谁拥有控制流那张图:下一步工程师写死的是 workflow,模型现场决定的是 agent。不是"能不能用 tool / 谁更强"。默认从 workflow 开始,agent 要挣它的复杂度。
为什么加大 context window 修不了 dilution?
dilution 是注意力行为问题(lost in the middle),不是容量问题。1M 窗口照样塌。解法是外部记忆 + 让模型自己决定 page in(MemGPT)。
LangGraph checkpointer 和 AlphaEvolve archive 的共同点?
都是把状态外部持久化(内化 vs 外部尺子)。区别:checkpointer 服务崩溃恢复,archive 服务演化采样 —— 形似神不同,别把某一个的用途安到两者头上。
"handoff = tool" 省掉了什么?
省掉一个专职做路由决策的 LLM。白嫖 LLM 已有的 tool-selection 能力当 router,加新 agent 只需在 tool 列表加一项。这是 L13→L16 "折叠中间层"的极致。
agent 数小时长跑 + 中途扣款 + 崩了精确断点续 + 扣款不重复,选什么?
Temporal + agent(activity 级重放,exactly-once 原生免费)。LangGraph + 幂等 tool 也能做但"精确断点"做不到(node 级 checkpoint)—— 题眼卡到这么死时最贴切是 Temporal。
output guardrail 能防 prompt injection 吗?
能挡明显泄露,挡不住编码外泄 / 间接注入 / tool-call 数据外泄。防御要 defense-in-depth 五层,且锚点搬到"动作符合用户原意吗"而非"内容可信吗"(PVE)。
agent 老出错,该等更强的模型吗?
通常不是。MASFT:失败是设计缺陷不是模型局限。88% 企业 agent 项目死在 runtime 不是 reasoning。答案是补一道缺失的 gate,不是 scale 模型。
怎么防 agent "假装成功"?
不信 agent 自述,重新探测真实状态验证(它说文件建好了,就去 ls)。成功由外部状态验证,不由 agent 宣布。落地成 succeeded() == (exit_code == 0)。
subagent 本质是什么?
worker 原语:隔离 state + 独立生命周期 + 只靠消息通信。进程 / 线程 / 新 context window 都是实现变体。它的"拥有自己 state" = 独立 context = 主 agent budget 不被烧。
选 agent 框架/运行时,你先问什么?
①要不要 agent(还是 workflow 就够)②多动态(谁拥有控制流)③怎么验证对错(外部 ground truth 从哪来)+ 失败/副作用能承受多脏。再叠上"该爬到栈的哪一层"和"匹配你现有 stack"。
